## 目标与共同约束

在一个 Open Terminal Docker 容器内，为每个 Open WebUI 账号提供持久工作空间，优先复用现有代码。文件和个人环境在正常使用中不串用，产品 API 检查资源归属；不建立对抗任意用户命令或代码的安全边界。

下表集中记录已确认决定，适用于全部需求与验收。原 D 编号保持稳定；本轮新增 D11 的工作账号 UID/主组 GID 范围，其余业务边界继续有效。

## 需求说明

### REQ-001 可信身份与工作空间唯一归属

**当前实现与剩余工作：** 账号/home 分配、缺用户头拒绝及保留账号拒绝已有实现（E02、E03）；仍需补齐完整 ID 唯一归属、UID/GID 区间分配、同名账号冲突和首次并发初始化。已修复的缺头回退保留为回归项。

通过管理员系统连接，将资源归属到 Open WebUI 认证的稳定账号。每账号一个持久空间，跨聊天、重新登录和修改显示名后保持归属；名称清洗、截断或上下文缺失不能使不同账号共用空间。

身份认证由 Open WebUI 负责，Open Terminal 校验管理员连接的服务凭据及约定用户上下文。缺失或不符合约定的身份不得回退默认服务用户；不据此新增逐请求账号回查、JWT 或用户数据库同步。实例 key 的保管与防护边界按 D01、D03。

**UID/GID 分配规则：**

- 新建 Linux 工作用户的 UID、私有主组的 GID 必须分别在 **10001–19999（含两端）** 内；UID 与 GID 分别查重，不要求二者数值相同。不同用户不得共用 UID 或私有主组 GID，已有占号应跳过，不能接管不属于该用户的账号或组。
- 任一编号池耗尽时明确返回可诊断的分配失败，不向区间外分配、不回退默认/共享账号，也不改动已有用户数据；并发准备及失败重试仍满足 AC-004、AC-023。
- 此范围仅约束工作账号及其私有主组，不改变 root、服务账号及附加组的既有 UID/GID 编号，也不限制既有合法的组成员关系维护。同一现存账号重复访问沿用原分配；仍存在的区间外账号不自动改号或迁移，其复用遵守原归属规则，不计作符合新建区间验收。旧容器销毁后账号已不存在的，按新建规则恢复。

| 编号 | 验收条件 |
| --- | --- |
| AC-001 | A、B 获得不同空间；A 跨聊天、重新登录仍访问原空间，改显示名不改变归属。 |
| AC-002 | 对清洗后前缀相同的不同标识、短标识及与系统账号同名的标识，不复用他人资源；不支持的标识明确失败。 |
| AC-003 | 系统连接拒绝未经上游认证的访问；纳入范围的 HTTP/WS 资源请求缺少或携带无效的约定身份时，不读写他人资源、不回退默认服务身份。界面、响应与接入配置不向普通用户交付实例 key。 |
| AC-004 | 同用户并发首次访问只形成一个可用空间；不同用户并发首次访问不串目录、账号、UID/私有主组 GID 或任务。 |
| AC-032 | 新建 A、B 工作账号的 UID 和私有主组 GID 均在 10001–19999 内，分别唯一；边界用例允许 10001、19999，不分配 10000、20000 或其他区间外编号。root、服务账号及附加组的既有 UID/GID 编号保持，不限制合法的组成员关系维护。 |
| AC-033 | 分别预占 UID/GID 后，新建分配跳过占号且不接管他人账号/组；任一池耗尽时明确失败，不越界、不回退共享账号、不改动已有用户数据。并发分配与失败重试满足 AC-004、AC-023。 |

### REQ-002 私有文件与个人资料访问

**当前实现与剩余工作：** 文件接口及普通路径检查可复用（E04、E12、E13）；剩余重点是符号链接与路径规则一致性、grep/glob 校验缺口，以及公共只读资料和辅助处理的正反向验证。

用户及 AI 助手通过文件 API 管理本人文件、技能与个人资料。覆盖列表、读写、替换、上传、下载、归档、移动、删除、搜索、对比、预览、静态文件服务及技能资源读取。浏览器隐藏上级目录不能替代接口检查；辅助处理同样受请求用户的路径和资源归属规则约束。

按 D01 排除任意命令/代码直接访问及恶意并发换链防护；按 D05、D08 处理共享基础资料和用户自行公开的服务。

### REQ-007 初始化、持久化与生命周期
